# 4주차 — 상권 유동인구 시뮬레이션 (동대문패션타운 관광특구)

가상인간(페르소나) 풀에게 "이 상권에 방문할지"를 물어보고, 방문한다는 응답을 유동인구
풀에 채워 넣는 방식으로 상권 유동인구를 시뮬레이션합니다. 시뮬레이션 결과(연령·성별·
시간대 비율)를 실제 상권 유동인구 데이터와 비교해 얼마나 일치하는지 수치화하는 것이
목표입니다.

## 상권 개요

| 항목 | 내용 |
|---|---|
| 상권명 | 동대문패션타운 관광특구 |
| 지정 | 2002년 5월, 서울시 1호 관광특구 (명동·이태원·잠실과 함께 지정) |
| 관할 | 서울 중구 |
| 범위 | 광희동1·2가, 을지로6·7가, 신당동 일부 (청계천~을지로6가~DDP 일대) |
| 주요 시설 | 두타몰, 밀리오레, 헬로apM, 굿모닝시티, 평화시장, apM PLACE, 디자이너클럽, DDP |
| 특징 | 패션 도소매 특화, 심야~새벽 영업(도매상권), 외국인 관광객(중국·일본·동남아) 비중 높음 |
| 상권_코드 | 3001493 (서울시 상권분석서비스) |

## 폴더 구성

```
4_district_simulation/
├── README.md
├── .env.example                        ← OPENAI_API_KEY 템플릿
├── data/
│   └── nemotron_personas_korea_demo.parquet  ← 가상인간 페르소나 풀 100만 명(인구통계 컬럼만)
├── dongdaemun_store_map.html            ← 매장 5개 지도 (추상 지도, 단일 파일)
├── dongdaemun_store_map_leaflet.html    ← 매장 5개 지도 (실제 OpenStreetMap, 단일 파일)
├── simulation_validation.html           ← 1차 시뮬레이션 검증 차트 (실제 vs 시뮬 비교)
├── visit_simulation.py                  ← 방문 시뮬레이션 v1 (방문 여부·시간대)
├── visit_simulation_v2.py               ← 방문 시뮬레이션 v2 (+ 매장 선택)
├── expand_30day.py                      ← v2 결과로 30일 매장별 방문 로그 생성 (API 불필요)
└── outputs/
    └── visit_simulation_results.csv     ← v1 결과 (5,000명 질의, 841명 방문)
```

## ① 상권·매장 준비

### 데이터 소스

| 필요 데이터 | 출처 | 비고 |
|---|---|---|
| 관광특구 유동인구(연령·성별·시간대·요일) | 서울열린데이터광장 — 상권분석서비스 추정 유동인구 | 2021Q1~2026Q1, 21개 분기 |
| 상권 내 업종별 점포 수 | 서울시 상권분석서비스(점포-상권) | 90개 업종 |
| 상권 중심좌표·면적 | 서울시 상권분석서비스(영역-상권) | 위도 37.5673 / 경도 127.0113, 606,058㎡ |
| 가상인간 페르소나 풀 | nvidia/Nemotron-Personas-Korea | 100만 행, 1주차~2주차와 동일 데이터셋 |

### 매장 유형 → 롯데 계열사 라벨링

실제 유동인구 데이터로 검증하는 게 목적이라, 상권에 실존하지 않는 업태(영화관·면세점·
테마파크)는 제외하고 실존하는 5개 유형만 사용했습니다.

| 매장 유형 | 롯데 계열사 | 실제 존재 근거 |
|---|---|---|
| 마트 | 롯데마트 | 슈퍼마켓 91개로 대체 라벨링 |
| 편의점 | 세븐일레븐 | 편의점 35개 |
| 카페 | 엔제리너스 | 커피-음료 106개 |
| 호텔 | 롯데시티호텔 | 여관 19개·게스트하우스 11개로 대체 라벨링 |
| 백화점 | 롯데백화점 | 던던 동대문점(구 롯데피트인, 롯데자산개발 운영·롯데백화점 MD 지원) |

> 던던 동대문점은 간판에 "롯데"가 없지만 운영사가 롯데자산개발(롯데그룹 계열)이고
> 롯데백화점 인력이 MD 구성을 지원한 실질적 롯데 계열 시설.

## ② 지도 시각화

매장 5개를 유형별로 색상 구분해 표시한 지도를 두 가지 방식으로 만들었습니다.

- **`dongdaemun_store_map.html`** — 외부 리소스 없는 순수 CSS/JS 추상 지도. 상권 경계(반경
  약 439m)와 매장 5개 핀, 업종별 실제 점포 수(마트 91·편의점 35·카페 106·호텔 30)만큼
  경계 안에 무작위로 뿌린 밀도 점 포함.
- **`dongdaemun_store_map_leaflet.html`** — Leaflet.js + OpenStreetMap 기반 실제 지도.
  같은 매장 5개를 실제 위경도에 배치. 인터넷 연결 상태에서 브라우저로 열어야 지도 타일이
  로드됨(외부 리소스 사용).

## ③ 방문 로직 + 집계

### v1 — 방문 여부만 판단 (완료)

`visit_simulation.py`. 페르소나 25명씩 묶어 OpenAI(gpt-5.4-mini)에게 "이 상권을 방문할지
(Y/N)"와 방문 시간대를 질의. 방문(Y) 응답이 목표 수만큼 채워지면(또는 안전 상한에
도달하면) 종료.

| 항목 | 값 |
|---|---|
| 에이전트 풀 | 1,000,000 (무작위 추출) |
| 질의한 에이전트 수 | 5,000 (안전 상한 도달로 종료) |
| 채워진 방문자 수 | 841 |
| 수락률 | 16.8% |
| 실제 비용 | $0.32 |

```bash
pip install openai python-dotenv pandas pyarrow
# .env.example → .env로 복사 후 OPENAI_API_KEY 채우기
python visit_simulation.py --target 999999 --max-agents 20000 --batch-size 25
```
기존 `outputs/visit_simulation_results.csv`가 있으면 이어서 진행(누적)합니다.

### v2 — 매장 선택 포함 (스크립트 준비 완료, 실행 대기)

`visit_simulation_v2.py`. v1과 동일하되 방문 시 5개 매장 중 어디로 갈지도 함께 판단.
결과 스키마가 달라져 별도 파일(`outputs/visit_simulation_v2_results.csv`)에 저장됩니다.

```bash
python visit_simulation_v2.py --target 999999 --max-agents 20000 --batch-size 25
```

### 30일 반복 + 매장별 집계 (스크립트 준비 완료, 실행 대기)

`expand_30day.py`. API 호출 없이 v2 결과를 바탕으로 30일치 매장 방문 로그를 생성합니다.
방문(Y) 판정자는 30일 중 1~4일 방문(가중치: 1일 55%·2일 25%·3일 12%·4일 8%)한다고
가정하고, 매장·시간대는 v2에서 판단한 값을 유지합니다(설계 가정이며 실측 데이터 아님).

```bash
python expand_30day.py
```
`outputs/daily_visit_log.csv`(일별 방문 로그), `outputs/store_summary.csv`(매장별 집계)
생성.

## ④ 검증 (1차 완료, v2 결과로 갱신 예정)

`simulation_validation.html`. v1 결과(841명) 기준 실제 유동인구 비율과 비교.

### 연령대 (accepted N=841)

| 연령대 | 실제(%) | 시뮬(%) | 오차(%p) |
|---|---|---|---|
| 10대 | 5.6 | 1.2 | 4.4 |
| 20대 | 17.8 | 29.6 | 11.8 |
| 30대 | 21.2 | 22.1 | 0.9 |
| 40대 | 20.7 | 17.4 | 3.3 |
| 50대 | 16.0 | 19.4 | 3.4 |
| 60대+ | 18.7 | 10.3 | 8.4 |

### 성별

| 성별 | 실제(%) | 시뮬(%) | 오차(%p) |
|---|---|---|---|
| 남 | 46.8 | 53.0 | 6.2 |
| 여 | 53.2 | 47.0 | 6.2 |
| **합계** | **100.0** | **100.0** | **MAE 6.2** |

### 시간대

| 시간대 | 실제(%) | 시뮬(%) | 오차(%p) |
|---|---|---|---|
| 00–06 | 17.0 | 2.6 | 14.4 |

전체 상관계수 **r = 0.72** (14개 구간 실제 vs 시뮬 비율 기준).

## 핵심 발견

- **연령·성별은 어느 정도 근접** (MAE 5.4%p, 6.2%p) — LLM이 나이·직업·거주지 기반으로
  그럴듯한 방문 성향을 반영함.
- **시간대는 크게 어긋남** (MAE 14.2%p) — 17-21시(저녁)에 51.5%가 몰려 실제(19.1%)보다
  과도하게 쏠렸고, 00-11시(새벽~오전)는 거의 선택되지 않음(실제로는 이 상권이 도매 시장
  특성상 새벽 영업 유동인구가 36.5%나 차지). LLM이 "관광특구 방문"을 일반적인 저녁
  나들이로 상상하는 경향이 있고, 프롬프트에 심야 도매 영업 특성을 명시했음에도 시간대
  판단에는 충분히 반영되지 않음.
- **전체 상관계수 r=0.72** — 방향성은 맞지만, 시간대 왜곡이 전체 상관관계를 끌어내림.
- 개선 여지: 시간대 판단 시 "이 상권은 새벽 도매 위주"라는 점을 더 강하게 프롬프트에
  강조하거나, 연령/성별과 시간대를 분리된 질문으로 나눠 판단시키는 방법을 다음 실행에서
  시도해볼 수 있음.
