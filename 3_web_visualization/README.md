# 3주차 — 페르소나 웹 시각화 (롯데하이마트)

`imsoowon/capstone`(week3, 롯데시네마)과 `kjyxee2/capstone`(03-simulation, 롯데면세점) 두 저장소의
형식 — 좌측 페르소나 패널 + 중앙 무대(캐릭터 이동/말풍선) + 하단 대화 로그 + 상단 진행률 바 — 을
참고해, 아직 다뤄지지 않은 계열사인 **롯데하이마트**를 배경으로 새로 제작했습니다.

## 시나리오 (신규 작성 — 기존 시나리오 재사용 아님)

> 롯데하이마트 화곡점 특가 소식이 세 주민의 단톡방에 올라온다. 처음엔 온라인(단톡방·검색)에서
> 각자 판단 기준으로 논의하다가, 방문 계획을 조율한 뒤 실제로 매장에 가서 — 그 중 두 명은
> 예정에 없이 같은 코너에서 마주쳐 — 대화를 이어가고 각자 구매를 결정한다.

2주차에서 사용한 주민 3명(우태은·김혁인·유화선)을 그대로 재등장시키되, 대사·행동은 하이마트
상황에 맞춰 5라운드·18턴 스케줄로 새로 작성했습니다.

| 라운드 | 위치 | 진행 내용 |
|---|---|---|
| 1. 단톡방 반응 | 집/온라인 | 특가 소식을 보고 각자 관심 품목과 첫 반응을 보인다 |
| 2. 개별 정보 탐색 | 집/온라인 | 직업/성향에 따라 다른 기준(AS·보증 / 설치 조건 / 리뷰·가성비)으로 알아본다 |
| 3. 방문 계획 조율 | 집/온라인 | 같이 갈지 따로 갈지, 언제(주말 vs 평일 저녁) 갈지 조율한다 |
| 4. 실제 방문 & 우연한 만남 | 매장(에어컨/청소기 코너) | 각자 계획대로 매장에 도착하고, 우태은·유화선이 청소기 코너에서 예정 없이 마주쳐 대화한다 |
| 5. 결론 | 계산대 | 각자의 최종 행동(구매)을 확정한다 |

페르소나별 차별점:
- **우태은** (의상 디자이너) — 원단 내구성을 따지듯 보증·AS 조건을 계약서 검토하듯 꼼꼼히 비교, 혼잡 회피
- **김혁인** (인테리어 필름 시공자) — 설치·배관 등 현장 전문성 기반 즉흥 판단, 사교적으로 동행 제안
- **유화선** (전화 상담원) — 예산과 실사용 리뷰 위주로 판단, 혼잡한 시간대 회피, 짧게 들르는 쪽 선호

## 행동(action) 설계

모든 턴은 5가지 행동 유형 중 하나로 분류되고, 로그·말풍선에 아이콘과 함께 표시됩니다.

| 유형 | 아이콘 | 의미 |
|---|---|---|
| MOVE | 🚶 | 다른 위치(집→매장 코너 등)로 이동 |
| TALK | 💬 | 특정 대상(target)에게 하는 발화 — 단톡방 전체 또는 특정 인물 |
| SEARCH | 🔍 | 온라인으로 정보를 찾아보는 행동 |
| REACT | 💭 | 짧은 반응·혼잣말 (예: 다른 사람의 소식에 대한 리액션) |
| BUY | 🛒 | 매장에서 실제 구매를 확정하는 행동 |

TALK 턴에는 `target`(발화 대상)을 명시해 누가 누구에게 말하는지 로그에서 바로 추적할 수 있게
했습니다 (예: `우태은 → 유화선`).

## 구현 방법

- **단일 HTML 파일** (`himart_stage.html`) — 외부 라이브러리·서버·빌드 과정 없이 브라우저에서 바로 실행
- **HTML/CSS**: 좌측 페르소나 카드(이름·직업·거주지·성향·현재 상태), 중앙 무대(집/온라인·에어컨 코너·
  청소기 코너·계산대 4개 존), 하단 콘솔 로그, 상단 라운드·경과시간·진행률 바
- **캐릭터**: PNG 캐릭터 시트 대신 CSS로 그린 색상 구분 원형 아바타를 사용해 파일을 가볍게 유지
  (단일 파일, 이미지 임베딩 없음)
- **JavaScript**: `TURNS` 배열(라운드·화자·존·행동유형·대상·대사·행동상세)을 데이터로 두고,
  `▶ RUN`(자동 재생, 3.2초 간격) / `다음 턴`(수동 진행) / `RESTART` 버튼으로 턴을 하나씩 재생.
  턴이 바뀔 때마다
  - 해당 화자의 캐릭터가 CSS `transition`으로 지정된 존(zone)까지 걸어서 이동
  - 캐릭터 위에 말풍선(대사 + 행동유형 아이콘 + 대상)이 페이드인
  - 좌측 카드가 활성화 테두리로 강조되고 "현재 상태"가 갱신
  - 하단 로그에 한 줄 추가, 상단 진행률 바/라운드 표시 갱신

### 왜 매 실행마다 LLM을 호출하지 않았는가

상용 LLM API(OpenAI/Claude 등)는 호출당 비용이 발생하고, 페이지를 열 때마다(혹은 새로고침마다)
실시간으로 호출하면 방문자 수에 비례해 비용이 계속 쌓이는 구조입니다. 이를 피하기 위해 **먼저
2주차 실험(`persona_chat.py`, v3 OpenAI 실행)에서 페르소나별 반응이 가장 뚜렷하게 갈렸던 진행
구조(라운드별 질문 → 서로의 발언을 참고해 합의로 수렴)를 참고해 대사·행동 스크립트를 사전에
직접 작성**했고, 이 시각화는 그 고정 스크립트(`TURNS` 배열)를 재생하는 방식으로 만들었습니다.
즉 방문자가 몇 번을 열어보든 추가 API 비용이 들지 않습니다. 실시간 생성이 필요하면 2주차
`persona_chat.py`처럼 API를 붙여 매 실행마다 다른 대화를 생성하도록 확장할 수 있습니다.

## 참고한 사례와 개선한 점

[가상 도시 주민 시뮬레이션 웹 시각화](https://velog.io/@chchxn/%EA%B0%80%EC%83%81-%EB%8F%84%EC%8B%9C-%EC%A3%BC%EB%AF%BC-%EC%8B%9C%EB%AE%AC%EB%A0%88%EC%9D%B4%EC%85%98-%EC%9B%B9%EC%9C%BC%EB%A1%9C-%EC%8B%9C%EA%B0%81%ED%99%94)
글을 참고해, 첫 버전(v1)에서 아쉬웠던 행동·상황 설계를 다음과 같이 보강했습니다.

- **행동 유형 단순화·명시화**: 자유 텍스트였던 행동을 MOVE/TALK/SEARCH/REACT/BUY 5개 유형으로
  정리하고, TALK 턴에는 발화 대상을 명시해 누가 누구에게 말하는지 로그에서 바로 추적되게 함
  (참고 사례의 "같은 장소에 있으면 대화를 우선하고, 발화 대상을 명시해 상호작용을 추적한다"는
  설계 원칙을 반영)
- **상황을 온라인→오프라인 2단계로 확장**: v1은 세 사람이 각자 흩어져서 반응만 하고 끝났지만,
  v2는 온라인 단톡방 논의(R1~3) → 실제 매장 방문(R4~5)으로 이어지게 하고, 계획에는 없던 **우태은·
  유화선의 매장 내 우연한 만남**을 추가해 대화가 자연스럽게 한 장소로 모이는 장면을 만듦
  (참고 사례가 "이천 문화센터에서 세 사람을 처음부터 한 자리에 모아 자연스러운 대화 흐름을
  유도"한 것과 같은 목적)
- **존(zone)을 4개로 확장**: 기존 매장 3개 코너에 "집/온라인" 존을 추가해, 캐릭터의 이동 자체가
  "논의 단계 → 실제 방문 단계"라는 상황 전환을 시각적으로 보여주도록 함

## v3 — 캐릭터 소개 패널 & 존별 색상 보강

사용자가 참고 이미지 2장(① 4존 매장 배경, ② 유화선·김혁인·우태은 3인 소개 카드 — 성격/좋아하는 것/
라이프스타일 키워드 구성)을 공유했으나, 이 세션은 채팅에 붙여넣은 이미지를 실제 파일로 받는
기능이 없어 원본 픽셀을 그대로 가져올 수는 없었습니다. 대신 같은 **구성**을 실제 페르소나
데이터(`2_character_chat/personas/residents.json`의 professional/sports/arts/travel/culinary
persona 필드)에 근거해 CSS로 재구성했습니다.

- **캐릭터 소개 패널** (`.intro-grid`, 상단 3열): 인물별 색상 pill 배지 + `성격`/`좋아하는 것`
  2×2 아이콘 그리드 + `라이프스타일 키워드` 태그. 예) 우태은 = 원단·재봉/종이책/와인·하이볼/둘레길
  산책(디자이너 실무·취미 기반), 김혁인 = 당구/삼겹살&소주/시공 공구/유튜브 예능(현장 전문성·
  사교성 기반), 유화선 = 아이돌 음악/모둠초밥/다이어리 쓰기/에버랜드(내향적 취미 기반)
- **존별 색상 보강**: 참고 이미지의 "존마다 다른 색 바닥 조명" 아이디어를 CSS `radial-gradient`
  타원(`.zone-glow`)으로 재현 — 집/단톡방=보라, 에어컨 코너=파랑, 청소기 코너=주황, 계산대=회색
- 이 변경도 이미지·외부 리소스 없이 순수 CSS만 사용해 단일 파일 구조를 유지했습니다.

## v4 — 원본 이미지로 교체

이후 사용자가 두 참고 이미지를 다운로드 가능한 Google Drive 링크로 다시 제공해줬고, 이번에는
`curl`로 직접 받아 **원본 픽셀을 그대로** 사용했습니다 (v3의 CSS 재구성 버전을 대체).

- **캐릭터 소개 패널**: 3인 카드 이미지를 인물별로 잘라(`Pillow`로 카드 경계 픽셀을 스캔해 정확한
  좌표 산출) 그대로 표시. 성격/좋아하는 것/키워드 텍스트도 전부 원본 이미지 그대로입니다.
- **무대 캐릭터 & 사이드바 아바타**: 같은 원본에서 인물 일러스트만(이름표·정보 패널 제외) 다시
  잘라 무대를 걸어다니는 캐릭터와 좌측 아바타로 사용.
- **매장 배경**: 참고 이미지를 그대로 무대 배경으로 사용. 존(원형 러그)의 실제 중심 좌표를
  픽셀 분석으로 구해(`home 12.8% / ac 36.7% / vac 61.0% / counter 85%`) 캐릭터가 정확히 그
  자리에 서도록 좌표를 갱신했습니다.
- **용량 최적화**: 원본 PNG(장당 1.5MB 안팎)를 그대로 쓰면 파일이 너무 커져서, 리사이즈 후
  JPEG로 재압축(배경 1200px/q85, 카드 480px/q87, 캐릭터 260px/q90)해 base64로 HTML에 직접
  삽입했습니다 — 여전히 서버·빌드 없이 파일 하나로 완결되는 구조를 유지하면서도 전체 용량은
  약 500KB 수준입니다.
- 이미지 자체는 여전히 이 세션에서 채팅에 "붙여넣은" 상태로는 받을 수 없었고, **다운로드
  가능한 링크(Google Drive 공유 링크 → 직접 다운로드 URL)로 받은 뒤에야** 실제 파일로 사용할
  수 있었습니다.

## v5 — 캐릭터 배경 투명화 & 존 정렬 수정

두 가지 피드백을 반영했습니다.

- **캐릭터 뒤 흰 배경 투명화**: 무대를 걸어다니는 캐릭터·좌측 아바타에 쓰인 이미지는 원래 카드
  배경색(라벤더/흰색/베이지)이 그대로 있는 사각형이라 어두운 무대 위에서 흰 박스처럼 떠 보였습니다.
  각 이미지 모서리에서 배경색을 샘플링한 뒤, 배경색과의 색상 거리를 기준으로 알파 채널을 계산해
  투명화(`Pillow`로 처리, 가장자리는 부드럽게 페더링)했습니다. 캐릭터 소개 카드(정보 패널 포함
  버전)는 카드 형태 그대로 두는 게 자연스러워 투명화하지 않았습니다.
- **존 경계를 벗어나는 문제 수정**: 기존에는 인물별로 고정된 픽셀 오프셋(예: 우태은 -58px)을 항상
  적용해서, 같은 존에 여러 명이 몰릴 때(예: 시작 시점엔 3명 모두 "집") 배경 이미지의 존 경계선
  밖으로 살짝 삐져나가는 경우가 있었습니다. 지금은 매 턴마다 **각 인물이 실제로 어느 존에 있는지
  추적**하고(`charZone`), 같은 존에 있는 인원 수에 맞춰 배치를 다시 계산합니다
  (1명 → 정중앙, 2명 → ±40px, 3명 → -52/0/+52px). 그래서 인원이 몰리거나 흩어질 때마다 자동으로
  간격이 재조정되어 항상 존 안에 들어갑니다.
