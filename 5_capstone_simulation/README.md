# 5 — 동대문패션타운 관광특구 상권 방문 시뮬레이션 (캡스톤 최종)

nvidia/Nemotron-Personas-Korea 페르소나 100만 명 풀에 "이 상권을 방문하겠는가"를 반복
질의해서 방문 수락자 500명을 채우고, 그 구성(연령·성별·시간대·요일)이 서울시 실제
유동인구 통계와 얼마나 일치하는지 검증한다. 기본 정보만 준 조건(시뮬레이션 1)에서
출발해 상권 분석 정보를 단계적으로 추가하며(시뮬레이션 2·3) 오차가 어떻게 바뀌는지,
그리고 남은 오차의 원인을 대조실험 2건으로 추적했다. 총 5개 실행으로 구성된다.

기존 `4_district_simulation_`, `4-2_district_simulation` 폴더의 탐색적 실험은 그대로
두고, 이 폴더는 처음부터 다시 구성한 최종 버전이다.

### 1) 시뮬레이션 1 — 기본 정보만

페르소나(나이·성별·직업·거주지·취미성향)와, 실제 데이터(추정유동인구·점포-상권)에 있는
내용만으로 만든 최소한의 상권 정보(상권명·상권코드·매장 유형별 점포 수)만 주고 질의했다.
몰 이름 같은 배경 지식은 데이터에 없는 내용이라 넣지 않았다.

- **질의 2,325명 → 수락 500명 (수락률 21.5%)**
- MAE — 연령대 3.66 · 성별 0.4 · 시간대 15.92 · 요일 18.09

### 2) 시뮬레이션 2 — + 1단계 상권 분석 결과

시뮬레이션 1과 동일 조건에, `data/stage1_district_facts.json`(팀원이 만든 1단계
프롬프트를 Claude Opus 4.8로 실행한 결과, 2026-08-24, 사용자 제공)에서 **한줄요약 +
대표업종_운영시간 + 방문목적**만 가져와 상권 설명에 추가했다(팀원 2단계 프롬프트 스펙
그대로).

- **질의 3,326명 → 수락 500명 (수락률 15.3%)**
- MAE — 연령대 4.47 · 성별 4.8 · 시간대 15.05 · 요일 20.32
- 시간대만 소폭 개선되고 나머지는 악화 — 특히 성별(0.4→4.8)과 요일(18.09→20.32)이
  뚜렷하게 나빠졌다. "도매·야간" 서술이 성별 이미지를 연상시키고, 낮장·밤장 정보를
  줬는데도 토요일 쏠림이 74.0%→83.8%로 더 심해졌다.

### 3) 시뮬레이션 3 — + 요일특성 + 반편향 지시

시뮬레이션 2 결과의 원인을 분석해 두 가지만 추가했다:
① `stage1_district_facts.json`의 **"요일특성"** 필드(2단계 스펙엔 없었지만 요일 판단에
가장 직접적인 정보라 추가) ② "상권 방문=주말 나들이" 선입견과 성별 고정관념에 의존하지
말라는 **반편향 지시문**.

- **질의 3,073명 → 수락 500명 (수락률 16.3%)**
- MAE — 연령대 4.41 · 성별 0.6 · 시간대 14.62 · 요일 19.49
- 성별은 반편향 지시문 한 줄로 거의 완전히 회복(4.8→0.6)됐지만, 요일은 정보를 추가하고
  지시까지 했는데도 거의 그대로였다(20.32→19.49, 토요일 76.8%로 여전히 압도적).

### 4) 대조실험 1 — "방문" 표현 5종 비교

"방문"이라는 단어 자체가 관광·나들이 어감을 줘서 요일 편향이 안 풀리는 게 아닐까
하는 가설로, 같은 300명(seed=42)에게 상권 정보·반편향 지시문은 시뮬레이션 3과 동일하게
유지한 채 동사구만 5가지로 바꿔 물었다: 방문할지(기존) / 들를 일이 있을지 / 가서 물건을
사거나 볼일을 볼지 / 이용할지 / 갈지.

| 표현 | 수락률 | 시간대 MAE | 요일 MAE | 토요일 비중 |
|---|---|---|---|---|
| 방문할지 (기존) | 16.0% | 12.70 | 21.01 | 83.3% |
| 들를 일이 있을지 | 18.3% | 13.62 | 20.49 | 76.4% |
| 가서 물건을 사거나 볼일을 볼지 | 12.0% | 14.15 | 20.21 | 75.0% |
| 이용할지 | 22.3% | 14.06 | 19.30 | 76.1% |
| 갈지 | 14.0% | 12.92 | **18.29** | 71.4% |
| *(실제 토요일 비중)* | | | | *11.7%* |

가장 나은 표현("갈지")도 실제와 여전히 크게 차이 나서, **동사 선택은 요일 편향의
핵심 원인이 아니었다**는 결론.

### 5) 대조실험 2 — 패션/섬유/액세서리 직업군 필터링

표현을 바꿔도 안 풀려서, 시뮬레이션 3 결과(500명)를 직업 텍스트로 나눠보니 판매·상인·
자영업 계열(22명, 4.4%)은 나머지(478명)보다 토요일 비중이 낮았다(59.1% vs 77.6%).
이 방향성을 직접 검증하기 위해 페르소나 풀 100만 명 중 의류·섬유·신발·가방·액세서리
관련 현직 종사자만 걸러낸 2,417명 풀에서 300명을 뽑아 시뮬레이션 3과 동일한 프롬프트로
다시 질의했다.

- **패션 직업군 표본 300명 질의 → 156명 수락 (수락률 52.0%, 일반 인구의 3배 이상)**
- 요일 MAE 19.49 → 17.89, 시간대 MAE 14.62 → 12.63 (모두 개선)
- 토요일 비중 76.8% → 64.7% (여전히 실제 11.7%와 큰 차이)

방향은 맞지만 효과가 작다 — **일반 인구 표본으로 특수 목적(B2B 도소매) 상권의 요일
패턴을 재현하는 데는 구조적 한계**가 있다는 쪽으로 결론.

## 페르소나 표현 (나이·성별·직업·거주지·취미·성향)

팀원의 2단계 프롬프트 예시는 인물 특성을 "나이/성별/직업/취미·성향"으로 표기했는데,
nvidia/Nemotron-Personas-Korea 원본에는 구조화된 인구통계 컬럼 10개(uuid, sex, age,
marital_status, occupation, district, province, housing_type, education_level,
family_type)와 별개로 `hobbies_and_interests`(취미·성향) 같은 자연어 텍스트 필드가
있다. `prepare_personas.py`가 HF 원본 9개 parquet 조각에서 이 11개 컬럼만 받아와
페르소나 풀을 만든다. 거주지는 팀원 프롬프트 예시엔 없었지만 원래 페르소나가 갖고 있던
기본 정보라 그대로 남겼다(사용자 확인). 결과적으로 다섯 실행 모두 페르소나를
"나이·성별·직업·거주지·취미·성향" 5개 필드로 LLM에 전달한다:

> 0) 나이:74 성별:남자 직업:하역 및 적재 관련 단순 종사원 거주지:광주-서구
> 취미·성향:주말이면 무등산 자락을 천천히 걸으며 땀을 빼고, 내려오는 길에 단골
> 목욕탕에서 뜨거운 물에 몸을 담그며 동네 친구들과 정치 이야기를 나누는 시간을
> 가장 아낍니다. (...)

취미·성향 텍스트가 길어서(최대 약 300자) 배치당 프롬프트 토큰이 늘어난다. 비용·속도가
부담되면 `--batch-size`를 25보다 낮춰(예: 10) 실행하면 된다.

## 시뮬레이션 1·2·3 프롬프트 설계 상세

**시뮬레이션 1**의 상권 설명은 실제 데이터 두 파일에 있는 내용만으로 만들었다(상권명·
상권코드·매장 유형별 점포 수). 몰 이름 같은 배경 지식은 데이터에 없는 내용이라 넣지
않았다:

> 동대문패션타운 관광특구(상권 코드 3001493)이라는 상권입니다. 이 상권 안의 매장 구성은
> 마트 91개, 백화점 0개, 편의점 35개, 카페 106개, 음식점 346개입니다.

세 시뮬레이션 모두 프롬프트 끝에 공통 지침을 넣었다(사용자가 준 팀원 프롬프트 참고):
"상권 정보는 '이곳이 어떤 장소인지'에 대한 설명일 뿐이니, 실제 방문객의 분포나 통계를
맞추려 하지 말고 인물의 성향만으로 독립적으로 판단하라."

**시뮬레이션 2**는 `data/stage1_district_facts.json`에서 한줄요약+대표업종_운영시간+
방문목적만 가져와 상권 설명에 추가한다(팀원 2단계 프롬프트 스펙 그대로). 팀원 원본과
다르게 진행한 부분을 투명하게 밝혀둔다:
- 원본은 페르소나 1명씩 물어보는 형태였지만, 500명 수락까지 채우려면 수천 명을 질의해야
  해서 batch-size(기본 25)명씩 묶어 질의한다.
- 원본 출력 스키마의 **"이유"(방문 이유 서술) 필드는 뺐다** — 수락률·분포만 필요하다는
  요구사항에 맞춰 토큰 비용을 줄이기 위함.
- 원본에 없던 **"요일" 필드를 추가했다** — 나중에 요구된 요일별 분포 비교를 위해
  필요해서 세 시뮬레이션 모두 동일하게 추가했다.

**시뮬레이션 3**은 시뮬레이션 2에 `stage1_district_facts.json`의 "요일특성" 필드와
반편향 지시문 한 문단만 추가한다:

> "상권 방문"이라고 하면 습관적으로 "주말 나들이"를 떠올리기 쉬운데, 이런 일반적인
> 선입견에 의존하지 말고 위 상권 정보(특히 요일별 특성)에 근거해서 요일을 판단하세요.
> 업종·방문목적은 성별과 무관하니, 성별에 대한 고정관념에 의존하지 말고 인물 개개인의
> 특성만으로 판단하세요.

이 지시문은 실제 방문객 통계(몇 %가 어느 요일/성별인지)를 알려주는 게 아니라 LLM이
흔히 갖는 일반적 선입견에 의존하지 말라는 것이라, "실제 분포를 맞추려 하지 마라"는
원칙과 충돌하지 않는다.

## 실행 방법

```bash
cd 5_capstone_simulation
pip install -r requirements.txt
cp .env.example .env    # .env에 OPENAI_API_KEY 채우기

# 0) 페르소나 풀 100만 명 생성 (최초 1회, 인터넷 필요, 5분 내외)
python prepare_personas.py

# 1) 실제 데이터 정리 (data/real_distribution.json 생성)
python prepare_real_data.py

# 실행 1~3: 시뮬레이션 (각 500명 수락까지)
python visit_simulation1.py --target 500 --batch-size 25
python visit_simulation2.py --target 500 --batch-size 25
python visit_simulation3.py --target 500 --batch-size 25
python compare_results.py --target 500

# 실행 4: "방문" 표현 대조실험 (n=300)
python ablation_visit_wording.py --n 300 --batch-size 25
python compare_wording.py

# 실행 5: 패션 직업군 대조실험 (n=300)
python ablation_fashion_occupation.py --n 300 --batch-size 25
python compare_fashion_occupation.py
```

- 각 스크립트는 `outputs/`에 이미 결과가 있으면 이어서 진행한다(같은 시드로 셔플하므로
  이미 처리한 만큼 건너뛰고 계속 질의).
- `--max-agents`(기본 5,000)는 예산 보호용 안전 상한. 실제 수락률은 15~22% 수준이라
  500명 채우는 데 보통 2,300~3,400명 질의가 필요했다(5,000이면 여유 있음).
- 모델은 모든 스크립트 기본값 `gpt-5.4-mini`이며 `--model`로 바꿀 수 있다.

## 종합 결론

1. **정보를 더한다고 항상 정확해지지는 않는다.** 시뮬레이션 1(기본 정보만)이 연령대·
   성별·요일 세 지표에서 가장 낮은 MAE를 유지했다. 상권 분석 정보를 추가한 시뮬레이션
   2는 오히려 성별·요일 오차를 키웠다.
2. **얕은 편향은 지시문 한 줄로 고쳐진다.** 성별 오차(MAE 4.8)는 "성별 고정관념에
   의존하지 말라"는 문장 하나로 거의 원상 회복됐다(0.6).
3. **깊은 편향은 지시문으로 잘 안 고쳐진다.** 요일 오차(MAE 18~20)는 명시적 사실
   정보(요일특성)와 반편향 지시문을 함께 줘도 거의 그대로였다.
4. **표현을 바꾸는 것만으로는 부족하다.** 동사구를 5가지로 바꿔봐도 토요일 쏠림은
   71~83% 범위를 벗어나지 못했다.
5. **구조적 원인은 페르소나 풀과 상권의 불일치로 보인다.** 동대문의 실제 평일 방문객
   상당수는 전국에서 물건을 떼러 오는 소매상인이라는 특정 직업군인데, 일반 인구 무작위
   표본에는 이 집단이 4~5%만 존재한다. 직업군을 좁히면 방향은 맞게 개선되지만
   (토요일 76.8%→64.7%), 완전히 해소되지는 않는다.
